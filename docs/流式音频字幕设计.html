流式音频字幕设计

描述音频输入、流式转写、翻译和可选预填之间的接口与调度。

技术方案与时序输入与接口预填字幕与修订验收

输入与接口

桌面入口负责选择音频来源，将 16 kHz、16-bit、单声道 PCM 的异步帧流传给 AudioSubtitleSession。帧时间戳以采集会话为起点。Windows 使用 ProcessLoopbackCapture 捕获所选进程树，文件回放或其他平台的采集器可以使用同一帧流契约。停止或更换程序时取消旧会话。

接口责任
ISpeechTranscriber接收 PCM，依次报告当前短句的快照。每条快照带原文、相对时间和可选语种。临时结果可回改，稳定前缀长度用 UTF-16 码元计数。后端能保证字符稳定时才标记前缀。定稿关闭当前短句，下一条更新开始新句。断句策略由转写适配器决定。
IStreamingTranslator为三种翻译返回累计译文。音频请求提交定稿和近期原文。ISubtitlePrefill 和 ISubtitleParagraphTranslator 分别提供可选的缓存预填和段落修订。
SubtitleUpdate分别推送最新原文预览和按行 ID 更新的译文。空预览清除当前临时原文。双语模式显示预览，定稿和修订仍使用现有的字幕行。

默认转写器 WhisperSpeechTranscriber 按能量、句尾静音和最长块时限切分音频，只报告定稿。Nemotron 按识别端点或时限提交短句，在字幕边界继续保留解码状态，并在相邻解码结果之间保留稳定前缀。Qwen3-ASR 本地 ONNX 与 Whisper 复用音频切块器，逐块输出定稿。桌面入口 App.axaml.cs 从设置选择转写适配器。模型下载与安装

预填与定稿翻译的时序

  1. 第一句定稿后进入翻译队列。翻译生成期间，转写任务继续接收第二句的音频，双语窗口可以显示第二句的临时原文。
  2. 第一句译完且定稿队列为空时，如果第二句已有稳定前缀，支持预填的翻译器可以用相同的翻译指令、近期原文和稳定前缀准备缓存。每句尝试一次，默认预算为 500 ms，可用 audio.prefillBudgetMs 调整，设为 0 时停用。
  3. 新定稿到达时取消正在进行的预填。正式翻译以完整定稿为输入，缓存命中和复用由推理适配器处理。预填超时、后端忙或后端不支持时，定稿照常翻译。

llama.cpp 适配器复用正式翻译的聊天模板，使用零输出预算的请求填充提示词缓存。匹配的 token 由服务端复用。默认 Whisper 路径没有临时前缀，因此不会产生主动预填请求。

即时层和修订层

  1. 定稿进入有界队列，队列满时优先保留新句。过期句和中文跳过。即时请求携带最近几条原文，在同一行 ID 上更新累计译文。
  2. 相邻短句满足行数和间隔时，字幕会话尝试空档修订。请求使用原文和行 ID，返回结构化逐行译文。有效结果替换原行。
  3. 新转写开始或新短句定稿时取消正在生成的修订。修订超时或失败时保留已显示译文。模型驻留和推理并发由翻译适配器管理。
  4. 字幕窗支持滚动、双语显示和标题栏拖动。位置单独保存，关闭或更换程序后在上次位置恢复。

说话者分段

ISpeakerDiarizer 从有界队列接收与 ASR 相同的 PCM 帧，按同一音频时钟输出说话者区间。翻译按原队列推进。标签结果到达时，字幕窗按时间交集更新已有行。相邻行属于同一位说话者时仅在第一行显示编号。归属不清楚时标为未确定，检测到同时发言时标为多人重叠。

Windows 可选使用 NeMo-Speech.cpp 和 Nemotron 3 Diarization CPU 模型。此分支发生错误时，字幕会话继续转写和翻译。安装入口

验收用例

  • 同时播放两个程序，检查只有所选进程树的声音进入字幕。
  • 在英日片段之间加入静音，检查短句出现和空档段落修订。
  • 用有临时结果的转写器连续输入两句。确认第一句生成译文时会显示第二句临时原文，且只有定稿会进入正式翻译。
  • 让第二句在预填过程中定稿，确认预填取消并继续翻译。使用只有定稿的转写器时，确认无需等待预填。
  • 修订期间继续发声，检查新短句优先以及旧 ID 的译文不会写入别处。
  • 拖动后停止并重开字幕，检查恢复位置和滚动。
